1. Startup sequence

Three stages, a few seconds, skippable. The text is the output of real checks, so the animation is never dead time. The ready frame appears only if every check passes; otherwise it names the check that failed.

Shape: chamfered corners, thin bronze trim, segmented meters, monospace for data and a condensed sans for headings. Scanlines and glow are optional and off by default; reduced motion is honoured. Check contrast on the real screen.



5. The idea in brief


    

  • Startup is the first health check. Machine text, then the loadup art, then the ready frame. Real checks run underneath: config resolve, daemon handshake, build identity, probe link.
    • 

  • A background daemon owns the probe pipe, the rolling recorder and the guardrails. The workbench is a client that can be closed without stopping recording.
    • 

  • Two probe profiles for now: LIGHT (normal play, rolling capture) and HEAVY (verbose trace). Three launch modes: Watch, Debug-live, Tandem.
    • 

  • The launcher starts the game suspended and injects the probe, as F4SE's loader does. The pause before resume is the sync point: the game does not run until the daemon says synced.
    • 

  • Protocol profiles set what each actor may do: OBSERVE, HUMAN, ASSIST, MACHINE. Writes are snapshotted and verified.
    • 

  • Line references such as PipMon.psc#L42-L44@hash let people, AI and tools point at the same lines and propose edits that are refused if the lines changed.
    • 

  • Before shipping any copied boot art, check each source repo's licence and Bethesda's asset terms. The safe path is original art in this style.
