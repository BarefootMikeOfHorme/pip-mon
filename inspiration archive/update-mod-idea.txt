3. ISSUES WE MIGHT CAUSE (System Pitfalls & Safeguards)
-----------------------------------------------------------------------------------
[!] ISSUE 1: In-Process Bus Overhead & Micro-Stutters
  - Risk: If the C++ Probe / F4SE plugin does heavy string formatting or file I/O 
    inside the game process, it will cause frame drops or engine thread starvation.
  - Safeguard: Keep the internal producer thread completely asynchronous. Use a 
    lockless ring buffer in shared memory (mmap) and write raw binary structs. 
    Defer ALL string parsing, line grouping, and UI generation to the external host.

[!] ISSUE 2: Papyrus Log Buffer Flooding (Log Spam Lockup)
  - Risk: An infinite loop or stack dump in Papyrus can output 40MB+ text files in 
    seconds, causing the UI watcher to freeze or exhaust system RAM.
  - Safeguard: Implement a rate-limiter & hash deduplication filter in the bus. 
    If the same error hash fires >50 times/sec, collapse it into a single atomic 
    item with a live counter badge (e.g., "Error X [x1450]") without allocating 
    new UI list entries.

[!] ISSUE 3: Unsafe Memory Reads During Live AOB Scanning
  - Risk: Scanning memory sections of Fallout4.exe while the game is running or 
    updating can trigger Access Violations (0xC0000005) or crash the process.
  - Safeguard: Ensure AOB pattern scanners run under SEH (__try / __except) or 
    `VirtualQuery` page-attribute checks to verify `PAGE_EXECUTE_READ` permissions 
    before reading pointer addresses.

[!] ISSUE 4: AI Context Window Over-Saturations
  - Risk: Sending raw, un-filtered 500-line stack dumps to the AI agent wastes 
    tokens and confuses the LLM with repetitive engine noise.
  - Safeguard: The "Send to AI" action button should extract ONLY the deduplicated 
    atomic stack object, associated script source code snippet, and target version 
    deltas before formatting the prompt payload.
